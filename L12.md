# Lesson 12: When Properties Collide

Course: AI Capabilities and Limitations (Claude Academy) Section: Putting it all together (lesson 12 of 13, about 20 min) Type: Short video/summary (3 min) + one exercise ("The Failure Diagnosis")

Note: the lesson names two diagnostic pairs explicitly. The pairings I mark "(my guess)" and the AI security examples are my own suggestions, so check them against the lesson video.

# Learning goals
Recognize that most AI failures involve two or more properties interacting
Diagnose common failure patterns by naming the properties at play:
hallucinated citations
long-conversation drift
confidently wrong math
agreeable bad premises
Apply a targeted fix based on which property is the limiting factor

# 1. Core idea

The four properties don't operate alone. Most real failures are two of them meeting. Once I can name which two, I know which fix to reach for.

# 2. The four properties (recap)
Property	                        One-line reminder
**Next Token Prediction**	   Output is a continued pattern, so it can sound right without being right
**Knowledge**	               Frozen at the cutoff; uneven, with source amnesia
**Working Memory**	         Fixed context window with a cliff; no learning from corrections
**Steerability**	           Instructions followed by pattern-matching; gap between words and intent

# 3. Diagnostic pairs                
Failure pattern	                           Properties colliding	                                                       Likely fix
**Hallucinated specifics / citations**	    Next Token Prediction + Knowledge (stated in lesson)	                   Verify specifics; use web search or provide the source
**Long-conversation**                      drift	Working Memory + Steerability (stated in lesson)	                 Re-supply context; restate the goal or start fresh
**Confidently wrong math**	Next Token Prediction + Steerability (my guess, from Lesson 10 "brittle arithmetic")	    Offload to code execution

Agreeable bad premise	Sycophancy (from Lesson 3, "how AI gets its character") + a weak spot in Knowledge (my guess)	Invite pushback; ask it to challenge my premise

The lesson names four fixes in total: verify specifics, re-supply context, offload to code execution, invite pushback.

# 4. Key takeaways
Real-world failures are usually two properties, not one.
Naming the properties points straight to the fix.
This diagnostic move is Discernment applied: I evaluate better when I know what kind of wrong I'm looking at.

# 5. Exercise: The Failure Diagnosis

Why: Naming which two properties collided changes the fix entirely.

Setup: Think of 2-3 times an AI output disappointed or surprised me (including during this course). Write 1-2 sentences each: what I asked, what I got, what was disappointing.

**Steps**
Walk through each event with the AI. Ask: "Based on the four properties (Next Token Prediction, Knowledge, Working Memory, Steerability), which ones were likely at play here, and why?"
Evaluate its diagnosis. Do I agree? If not, push back. (Remember the sycophancy fingerprint from Lesson 3: the AI may agree with my framing too readily.)
For each diagnosis, ask: "Given that diagnosis, what's the most targeted fix?" Test the fix on a similar task if I can.

Then review the Lesson 1 task list with all its annotations:

Lesson 2	Property tags

Lesson 5	Knowledge flags
Lesson 6	Context needs
Lesson 7	Goal statements

For the tasks that gave the most trouble, name the two colliding properties and write the diagnosis next to each task.

# Quick revision
Most failures = two properties colliding.
Name the pair, then pick the fix: verify specifics, re-supply context, offload to code, invite pushback.
Stated pairs: NTP + Knowledge (hallucinated specifics), Working Memory + Steerability (long-conversation drift).
Don't accept the AI's diagnosis blindly. Push back (sycophancy).
Diagnosing = Discernment applied.
Link to AI Security (my goal)
Hallucinated specifics in security work (fake CVE numbers, invented tool names) are a real risk, so always verify against the original source.
Working Memory + Steerability is where prompt injection and lost safety rules show up: a rule can fall out of context, and a hidden instruction can steer the model.
A failure diagnosis is like an incident post-mortem: name the cause, then apply a specific control instead of a generic one.
Agreeable bad premises: an AI that agrees too easily can approve a weak security plan, so I should ask it to attack my plan.
