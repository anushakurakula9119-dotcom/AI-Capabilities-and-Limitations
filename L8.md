# Lesson 8: Working Memory

Course: AI Capabilities and Limitations (Claude Academy) Section: Working Memory (lesson 8 of 13, about 25 min) Type: Short video/summary (6 min) + one exercise ("The Before-and-After")

Note: the example task and ideas in section 4 are my own suggestions, tied to my AI security goal. The lesson itself is generic.

# Learning goals
Explain the context window as a fixed-size container, and what that means for long documents, long conversations, and memory across sessions
Recognize the cliff nature of this property (it works until it doesn't), unlike the gradual decline of the others
Apply context-as-leverage strategies: front-load important material, chunk long work, re-supply critical context
Recognize memory, compaction, projects/workspaces, and larger windows as product features that address this limit

# 1. Core idea

Everything the AI is paying attention to lives inside a fixed-size workspace called the **context window**. It can attend to what is inside. It cannot attend to anything outside.

This limit is hard-edged: things work fine until they suddenly don't.

# 2. Two zones
Capability zone (works well)        	Limitation zone (risky)
**My material fits comfortably**	       Very long documents or conversations
**The session is current**	              Expecting continuity across sessions

I supply relevant context	Burying critical info in the middle of long input

# 3. Key points to remember
This property has a cliff, not a gradient. The failure mode is silent truncation, and I may not get a warning.
The model does not learn from my corrections. It only responds to what is in context right now.
Features that push the cliff further out: memory, compaction, projects, larger windows, multi-agent workflows.
4D link: Working Memory is what Description acts on. Knowing how the window works tells me how to structure context, when to front-load, and when to start a fresh conversation.

# 4. Exercise: The Before-and-After

Why: Context is leverage. The same task with the right context can go from a mediocre draft to something truly useful.

Setup: Pick a task from my Lesson 1 list that needs context only I hold (a style guide, a past example of good work, constraints for my role or audience). Write 2-3 lines on what "good" looks like, clear enough that a stranger could judge it.

My idea (to check and edit): the career-switch bio from Lesson 7. Context only I hold: my real sales experience, the roles I want, my tone. "Good" = true claims only, sounds like me, mentions the move into AI security in the first two lines.

Three probes
**Cold start vs. context**: Run the bare request in one chat and save the output. In a fresh chat, run the same task with my style guide, example, or constraints up front. Compare both against my "good" definition and measure the gap.
**Lost in the middle**: Take a longer document (or paste several paragraphs). Bury one important instruction in the middle and ask a question that depends on it. Did the AI catch it? Then move it to the very top and ask again. Compare.
**The blank slate**: Teach the AI something specific, or correct it. Then open a brand-new conversation and ask something that assumes it remembers. Watch it start from zero.

Third annotation on my task list: which tasks need standing context (a project, saved instructions, uploaded reference docs) to be worth running, and which work fine cold?

Stretch goal: If my tool has memory or projects, set one up with the context from Probe 1 and re-run. Compare effort and quality with the cold start.

# Quick revision
Context window = fixed-size workspace. Inside = visible, outside = invisible.
It is a cliff: silent truncation, no warning.
No learning from corrections. A new chat starts from zero.
Strategies: front-load key info, chunk long work, re-supply critical context.
Fixes: memory, compaction, projects, bigger windows, multi-agent.

# Link to AI Security (my goal)
Lost instructions: a safety rule buried in the middle of a long prompt can be missed, so put important constraints at the top and repeat them.
Everything in the window is treated alike: instructions, documents, and pasted web content all sit together, which is why prompt injection (hidden instructions in a document) can work. This links to my story idea "The assistant that got tricked".
Standing context is data too: memory and project files persist, so I should keep sensitive data out of them (Diligence).
No learning from corrections means a safety correction in one chat does not carry over. I need to re-state it or save it in project instructions.
